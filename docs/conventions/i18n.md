# i18n

The interface exists in Spanish and English through `next-intl`; the locale follows the browser, can be switched from the sidebar, and `en` is the fallback.

## Rules

- Every user-facing string goes through `useTranslations` in client components or `getTranslations` in server code. This includes JSX text, `aria-label`, `placeholder`, `title`, `alt` and toast or dialog copy.
- Messages live in `app/src/messages/es.json` and `app/src/messages/en.json`; both files have the same key set at all times.
- Keys are namespaced as `{page or component}.{element}`, for example `sidebar.newDiagram`, `login.password`, `editor.saveFailed`.
- Dates and numbers are rendered with `useFormatter` from `next-intl`, never with `toLocaleString`, `Intl.*` directly or manual formatting.
- The Excalidraw component receives `langCode` derived from the active locale so its own UI follows the app.
- Locale detection and the request config live in `app/src/i18n/`.

## Not translated

- Diagram names and any other content the user typed.
- `data-testid` values, log messages, thrown error messages meant for developers.
- Test files under `app/tests/`.
