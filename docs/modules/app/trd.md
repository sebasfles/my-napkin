# app: technical

The editor shell and the auth gate exist: the layout, the embedded editor, the theme, the locale, and the password that guards all of it.
Persistence and the diagram routes do not, and are marked planned below.

## Structure

| Path | What | Status |
|---|---|---|
| `app/src/app/layout.tsx` | Root layout, sets `lang`, mounts the intl and theme providers | now |
| `app/src/app/page.tsx` | Sidebar plus editor, server component | now |
| `app/src/app/globals.css` | Tailwind and the theme tokens (CSS variables, light and dark) | now |
| `app/src/components/` | Editor wrapper, sidebar, theme and locale toggles, login form, logout button | now |
| `app/src/components/ui/` | shadcn/ui components, generated by its CLI | now |
| `app/src/i18n/` | `next-intl` request config and locale resolution | now |
| `app/src/lib/` | Pure helpers: theme resolution, editor language mapping, hydration gate, session tokens, gate paths, env accessors | now |
| `app/src/messages/{es,en}.json` | `next-intl` messages, one key set for both locales | now |
| `app/src/proxy.ts` | The request gate: every path but the allowlist needs a valid cookie | now |
| `app/src/app/login/page.tsx` | Password form | now |
| `app/src/app/api/login/route.ts` | POST login | now |
| `app/src/app/api/logout/route.ts` | POST logout | now |
| `app/tests/unit/` | Vitest, pure logic only | now |
| `app/tests/e2e/` | Playwright, one spec per flow | now |
| `app/src/app/api/diagrams/route.ts` | GET list, POST create | planned |
| `app/src/app/api/diagrams/[id]/route.ts` | PATCH rename, DELETE | planned |
| `app/src/app/api/diagrams/[id]/urls/route.ts` | GET presigned URLs for the scene | planned |

`src/lib/` will also hold the dynamo and s3 helpers once persistence lands.
The gate is `proxy.ts`, not `middleware.ts`: Next 16 renamed the file, and it runs on the Node runtime, so the same Web Crypto code signs the cookie in the route handler and verifies it in the gate.

## Endpoints owned

The two auth routes exist; the five diagram routes are planned.

| Method | Route | Purpose | Status | Spec |
|---|---|---|---|---|
| POST | `/api/login` | Validate `APP_PASSWORD`, set signed session cookie | now | none |
| POST | `/api/logout` | Clear the cookie, answer 303 to `/login` | now | none |
| GET | `/api/diagrams` | List diagrams, Scan on DynamoDB | planned | none |
| POST | `/api/diagrams` | Create diagram id and name in DynamoDB | planned | none |
| PATCH | `/api/diagrams/[id]` | Rename, or touch `updatedAt` after a scene PUT | planned | none |
| DELETE | `/api/diagrams/[id]` | Delete in DynamoDB and S3 | planned | none |
| GET | `/api/diagrams/[id]/urls` | Presigned GET and PUT URLs for the scene | planned | none |

`/api/login` answers a stable machine code on failure and the client maps it to the translated message, so the route carries no copy.
Every other route is behind the gate and never sees an anonymous request.

Jobs, listeners or scheduled work: none.

## Locale and theme

The locale is resolved per request in `src/i18n/`, from the `NEXT_LOCALE` cookie and then `Accept-Language`, with `en` as the fallback.
There is no `[locale]` route segment, so the route table above is the whole of it.
The theme is `next-themes` with the class strategy, persisted in localStorage, and the editor receives both as props.

## Depends on

- `@excalidraw/excalidraw` npm package: the editor component, loaded client-side only.
- DynamoDB table (diagram index) and S3 scenes bucket: planned, not yet reached from code.

## Depended on by

- `deploy` (`.github/workflows/`): builds this module with OpenNext and updates the Lambda.
- `infra` (`infra/`): provisions the env vars this module reads.

## Configuration

`APP_PASSWORD` and `SESSION_SECRET` are required, documented in `app/.env.example` and read through `src/lib/env.ts`.
The accessors run per request and never at module import, so a build with no secret in the environment still succeeds and a request without one fails loudly.
Planned: the table and bucket names passed by Terraform as Lambda env vars.
Locale and theme are never configured; both are read from the browser and persisted client-side.

## Testing

- Lint: `npm run lint` (ESLint, then Prettier in check mode).
- Typecheck: `npm run typecheck`.
- Unit: `npx vitest run`, over `tests/unit/`, Node environment, pure functions only.
- E2E: `npx playwright test --workers=1`, run on a developer machine and in `e2e-dev.yml` against `napkin.dev.sdfles.com`; `ci.yml` runs none.
- Playwright starts `npm run dev` itself unless `BASE_URL` is set, and reads `APP_PASSWORD` and `SESSION_SECRET` from `.env.local` to start it and to log in.
  It never adopts a server already on the port; a busy port is an error, because that server is usually another workspace's tree.
- Install: `npm ci`. Build for AWS: `npx open-next build`.
