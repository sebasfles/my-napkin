# app: technical

The shell, the auth gate, the workspace of diagrams and folders, the five diagram routes and the save and load path all exist.
Nothing here is planned.

The gate is `proxy.ts`, not `middleware.ts`: Next 16 renamed the file, and it runs on the Node runtime, so the same Web Crypto code signs the cookie in the route handler and verifies it in the gate.
The pages are client driven: no server component reads DynamoDB or S3, and every read and write goes through `/api`.

`/d/[id]/page.tsx` renders `null`, and that is the point rather than an oversight.
The App Router keys a dynamic segment by its parameter, so anything the page holds is thrown away on every `/d/a` to `/d/b`, including the scene already on screen.
The editor surface therefore lives in the layout, which survives: it reads the open diagram from the address, the same source the sidebar and the tab bar read, and the route exists only to name it.
Move the editor back into the page and the canvas blanks on every tab switch; `docs/modules/app/ard.md` carries the measurement.

## Endpoints owned

All seven exist.

| Method | Route | Purpose | Spec |
|---|---|---|---|
| POST | `/api/login` | Validate `APP_PASSWORD`, set signed session cookie | none |
| POST | `/api/logout` | Clear the cookie, answer 303 to `/login` | none |
| GET | `/api/diagrams` | List every item, diagrams and folders alike, Scan on DynamoDB | none |
| POST | `/api/diagrams` | Create a diagram or a folder, in the root or in a folder, or a library, which is always global | none |
| PATCH | `/api/diagrams/[id]` | Rename, move, pin, lock, link libraries, or record what the browser just uploaded | none |
| DELETE | `/api/diagrams/[id]` | Delete a diagram and its scene object, a library and both of its objects, or a folder and everything under it | none |
| GET | `/api/diagrams/[id]/urls` | Presigned scene urls, 5 minutes, and whether the diagram is locked; a second pair for a library's items; 404 when it is gone or is a folder | none |

One PATCH carries one intent: a name, a parent, a pin flag, a lock flag, the list of linked libraries, or the counts the browser measured after an upload.
A library's counts are their own intent, carrying `itemCount` and conditional on the item being a library, so a library save can never land on a diagram and a diagram save never brings an item count; that costs no extra read on the save path.
The `items` pair in the `/urls` answer is what tells the editor which flavour of canvas it opened, so it never waits for the item list to know.
It answers 400 to a body that changes nothing, 404 when the item is gone and 409 when a scene write is refused because the diagram is locked, which is also the only refusal the `/urls` route can express by handing back no upload signature at all.
A move or a pin is the one PATCH that reads before it writes: it lists the table once and puts the destination through `tree.ts`, so 400 covers a parent that is the item itself, one of its descendants, a missing item or a diagram, and a pin aimed at a folder.
Creating a folder writes no scene object and `/urls` answers 404 for one, so every scene object still belongs to exactly one diagram.
`/api/login` answers a stable machine code on failure and the client maps it to the translated message, so the route carries no copy.
Every other route is behind the gate and never sees an anonymous request; the browser turns the gate's 401 into a trip to `/login`, so an expired session interrupts the user instead of failing quietly.
The presigned PUT is signed with `Content-Type: application/json` in its signed headers, so the browser has to send exactly that.
Every browser call to `/api/*` carries `x-amz-content-sha256`, set by `src/lib/signed-fetch.ts`, because CloudFront's Origin Access Control signs the request to the Function URL and rejects a mutating request whose body it cannot hash.
The presigned S3 calls in `src/lib/api.ts` (`loadScene`, `putScene`) never go through that wrapper, since they never reach CloudFront.
Reference: `docs/modules/infra/ard.md`, "Lambda Function URL over API Gateway as the CloudFront origin".

Jobs or scheduled work: none; the only listener the app installs outside React is the keyboard one below.

## Keyboard

A global shortcut is one `keydown` listener on `window` in the capture phase, which is the first stop on the way down, so it decides before the editor's own handlers see the key.
It claims a chord only on an exact match, then calls `preventDefault` and `stopPropagation`; anything it does not claim it leaves untouched, which is what keeps a third-party canvas usable.
The match reads `event.code`, never `event.key`, because Alt rewrites `key` on several keyboard layouts.
`shortcuts.ts` holds the matching as one pure table and `<Shortcuts />`, mounted in the `(editor)` layout, holds the only listener: a new chord is a line in that table, never a second listener, because two listeners on the same event decide in mount order and that order is not a thing anyone reasons about.
A chord that drives the shell calls a store function that reads its own source at call time, so the listener holds no state of its own and registers once.

## Page metadata

The head is the metadata API's alone: `title`, `description`, `application-name`, `robots: noindex, nofollow` for a private site, and a `theme-color` per colour scheme, plus the file conventions that emit the icon and manifest links.
Only the title is set at runtime, by a client component in the `(editor)` layout, because the open diagram's name lives in the list the browser fetched and `generateMetadata` runs on the server, which is not allowed to read the table.
`icon.svg` is the source of every raster: it carries both colour schemes in a `@media` block inside the file, which is what browsers honour for a favicon, and `scripts/icons.mjs` rasterises the PNG, apple touch and `.ico` sizes from it so they cannot drift from it.
They are committed; the script runs by hand when the mark or the palette changes.
The build splits them: `favicon.ico` and the two `public/` PNGs land in the assets bucket, while `icon.svg`, `icon.png`, `apple-icon.png`, the manifest and `robots.txt` are routes the Lambda answers.
All of them are reachable without a session, because the gate treats a root path with an extension as public, and the e2e fetches every one of them from a request context that carries no cookie.

## Typeface, locale and theme

Geist Sans and Geist Mono come from the `geist` package, which is `next/font/local` over woff2 files it ships, so the build reaches no font host and the browser loads them from this origin; they are bound to Tailwind's `--font-sans` and `--font-mono`, and the editor keeps its own, since `.excalidraw` sets `font-family` on itself.
The locale is resolved per request in `src/i18n/`, from the `NEXT_LOCALE` cookie and then `Accept-Language`, with `en` as the fallback.
There is no `[locale]` route segment, so the route table above is the whole of it.
The theme is `next-themes` with the class strategy, persisted in localStorage, and the editor receives both as props.

## Configuration

`APP_PASSWORD`, `SESSION_SECRET`, `DIAGRAMS_TABLE` and `SCENES_BUCKET` are required, documented in `app/.env.example` and read through `src/lib/env.ts`.
The accessors run per request and never at module import, and both AWS clients are built on first use, so a build with nothing in the environment still succeeds and a request without a variable fails loudly.
The region and the credentials come from the environment the process runs in, never from an argument in code; `docs/TRD.md` says why the local workspace needs one variable more than AWS does.
Locale and theme are never configured; both are read from the browser and persisted client-side.

## Testing

- Lint: `npm run lint` (ESLint, then Prettier in check mode).
- Typecheck: `npm run typecheck`.
- Unit: `npx vitest run`, over `tests/unit/`, Node environment, pure functions only.
- E2E: `npx playwright test --workers=1`, run on a developer machine and in the `e2e-dev` job of `deploy-dev.yml` against `napkin.dev.sdfles.com`; `ci.yml` runs none.
- Playwright starts `npm run dev` itself unless `BASE_URL` is set, and reads `APP_PASSWORD` and `SESSION_SECRET` from `.env.local` to start it and to log in.
  It never adopts a server already on the port; a busy port is an error, because that server is usually another workspace's tree.
  The port is load bearing, not a default: the dev scenes bucket's CORS allows `http://localhost:3000` and the deployed dev host and nothing else, so serving the app anywhere else leaves it answering 200 while every presigned scene GET is blocked and the editor never paints.
  A busy port therefore means waiting, not moving.
- `retries` is 1 in CI and 0 locally, so a local run is the stricter of the two and a timeout CI would have retried away is fatal here.
  A local red is worth reading before it is re-run.
- The repositories are tested with `aws-sdk-client-mock`, the saver with injected ports and fake timers, so the unit suite needs no credentials.
- A spec removes what it created, through `removeItemsCreatedHere`, and the helpers wait for the sidebar to finish loading before they count anything in it.
  Every one of those deletes goes through the row's own menu, so no test code computes a payload hash; a library is located by its id, since an import names it after its file and two rows can briefly share a name.
- A spec that means "the first row of the list" scopes its locator to `itemList`.
  The pinned section renders above that list from the same row component and carries the same `data-testid`, so an unscoped first match silently becomes "the first diagram row on the page" the moment anything is pinned.
  Counting a list that has not rendered answers zero, which makes a cleanup pass while leaving rows in the table every other spec and Sebastian share.
- Install: `npm ci`. Build for AWS: `npx open-next build`.
